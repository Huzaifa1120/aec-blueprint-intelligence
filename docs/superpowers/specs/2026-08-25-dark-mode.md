# Dark Mode — Light & Dark Backgrounds

**Date:** 2026-08-25
**Scope:** Frontend only. Class-based theming via `next-themes`, a designed `.dark` token layer in
`frontend/src/styles/tokens.css`, narrow hardcoded-color cleanup, and one header insertion
(`ThemeToggle`) in `AppShell.tsx`.
**Out of scope:** Backend; no route changes; no redesign of any page beyond token semantics.

## Goal

Users get light and dark backgrounds across the app: the theme follows the OS setting by default,
a header toggle overrides it, and the choice persists. No flash of wrong theme on load.

## Theme behavior

- `next-themes` with `attribute="class"`, `defaultTheme="system"`, `enableSystem`,
  `disableTransitionOnChange`; provider mounted in `frontend/src/app/providers.tsx`;
  `<html suppressHydrationWarning>` added in `layout.tsx`.
- Toggle: new `frontend/src/components/layout/ThemeToggle.tsx` client component — ghost icon button
  (lucide Sun/Moon), `aria-label="Toggle theme"`, mounted-guard against hydration mismatch, placed
  in the AppShell header nav after the Catalog link. Icon swap animates ~150ms ease-out; global
  reduced-motion token zeroing covers `prefers-reduced-motion`.

## Token strategy (core rule)

Brand constants are identity, not surface — they stay FIXED in both themes:
`--ink-black: #12130f`, `--paper: #faf9f5` never change value. This keeps every literal
ink-black/paper surface (header/footer chrome, ProtocolCard, homepage hero) correct in both modes.

A new `.dark { ... }` block in `tokens.css` overrides only semantic layers:

- Canvas/background → deep warm ink family (`#12130f`); cards/elevations step up (`#1a1b15`,
  `#22231b`); borders become hairline light; input/popover follow.
- The ink TEXT scale inverts under `.dark` (`--ink-700/900` → paper-family, `--ink-500/300` →
  lightened steel ramp) so existing `text-ink-*` components theme automatically.
- Confidence tiers brighten for dark contrast: measured green `#34a06e`, derived amber `#f7b944`,
  assumed red `#e0604f`; tint backgrounds (green-tint, accent-wash) become translucent dark-safe
  equivalents.
- `--ring` stays amber.

`globals.css` adds Tailwind v4's class-based dark variant:
`@custom-variant dark (&:is(.dark *));` so shadcn's existing `dark:` utilities activate.

Exact hex values above are design intent for the implementer to fine-tune ±1 step while keeping
WCAG-legible text contrast; final values live only in `tokens.css`.

## Hardcoded-color cleanup (narrow)

Only literal colors that mean "surface" convert to semantics:

- `ReexportRequest.tsx`: card `bg-paper border-steel` → `bg-card border-border`.
- Homepage step cards in `page.tsx`: `bg-paper … border-outline-variant` → `bg-card border-border`
  (hover stays amber).
- Brand-by-identity literals stay untouched: AppShell header/footer ink chrome, ProtocolCard,
  homepage hero band, `design-system/page.tsx` (documents raw palette by definition).

## Dark-chrome separation

Header/footer stay `bg-ink-black text-paper` in both themes. On the dark canvas they separate via
existing hairlines plus `dark:` border adjustments where needed so chrome edges stay visible.

## Compatibility guarantees

- No test selectors, aria labels (outside the new toggle's own), or copy strings change.
- Existing suites must pass unmodified: Vitest unit suite and Playwright mocked e2e.
- `DropZone`, quality-gate components, and estimate flows behave identically in light mode.

## Verification

- `bun run typecheck && bun run lint && bun run format:check`
- `bun run test` (unit) and `bun run test:e2e` (mocked) fully green
- Manual: toggle switches instantly and persists across reload; OS scheme change is followed live
