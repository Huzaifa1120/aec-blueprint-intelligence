# Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Class-based light/dark theming across the app — OS-default with a persistent header toggle, zero flash, brand-safe token strategy.

**Architecture:** `next-themes` provider wraps the app; a `.dark` block in `tokens.css` overrides semantic layers only while brand constants (`--ink-black`, `--paper`) stay fixed; narrow conversion of literal "surface" colors to semantics; one new `ThemeToggle` client component inserted into the existing header nav.

**Tech Stack:** next-themes (new dep), Tailwind v4 `@custom-variant dark`, existing shadcn-style primitives, Vitest + Testing Library, Playwright mocked project.

**Spec:** `docs/superpowers/specs/2026-08-25-dark-mode.md`

## Global Constraints

- Brand constants NEVER change value or flip: `--ink-black: #12130f`, `--paper: #faf9f5` stay literal in `:root`; no `.dark` override may redefine them.
- Hex values live ONLY in `frontend/src/styles/tokens.css` (+ the two pre-existing exceptions: `globals.css` selection rule, design-system page swatches). No new hex anywhere else.
- Animate transform/opacity only; toggle icon treatment ≤200ms ease-out; global reduced-motion zeroing applies automatically.
- Preserve all existing test selectors, aria-labels, copy strings. Only NEW aria-label allowed: `Toggle theme`.
- Package manager Bun; run from `frontend/`. Unit tests: `bun run test`. E2e mocked: `bun run test:e2e`.
- This is NOT the Next.js you know: consult `frontend/node_modules/next/dist/docs/` before Next-specific APIs (only `suppressHydrationWarning` on `<html>` is used here).
- Known-green baseline: `src/lib/designTokens.test.ts` requires anchor hexes somewhere in tokens.css — adding `.dark` must not remove `:root` anchors.
- No code comments. No emojis. Commit AND push after each task (user directive). If git index.lock collides, wait 2s, retry once. Never stage `backend/` files (a parallel session owns them).

- [ ] **Step 2: Wire the provider**

In `providers.tsx` wrap the existing tree (ThemeProvider outermost):

```tsx
"use client"

import { QueryClient, QueryClientProvider } from "@tanstack/react-query"
import { ThemeProvider } from "next-themes"
import { useState } from "react"
import type { ReactNode } from "react"
import { TooltipProvider } from "@/components/ui/tooltip"

export default function Providers({ children }: { children: ReactNode }) {
  const [queryClient] = useState(
    () =>
      new QueryClient({
        defaultOptions: {
          queries: {
            staleTime: 30_000,
            retry: 2,
            refetchOnWindowFocus: false,
          },
        },
      }),
  )
  return (
    <ThemeProvider attribute="class" defaultTheme="system" enableSystem disableTransitionOnChange>
      <QueryClientProvider client={queryClient}>
        <TooltipProvider delayDuration={200}>{children}</TooltipProvider>
      </QueryClientProvider>
    </ThemeProvider>
  )
}
```

- [ ] **Step 3: Implement**

`ThemeToggle.tsx`:

```tsx
"use client"

import { Moon, Sun } from "lucide-react"
import { useTheme } from "next-themes"

import { Button } from "@/components/ui/button"

export function ThemeToggle() {
  const { resolvedTheme, setTheme } = useTheme()
  const isDark = resolvedTheme === "dark"
  return (
    <Button
      variant="ghost"
      size="icon-sm"
      aria-label="Toggle theme"
      title="Toggle theme"
      onClick={() => setTheme(isDark ? "light" : "dark")}
      className="text-paper/70 hover:bg-white/10 hover:text-paper"
    >
      <Moon className="size-4 dark:hidden" />
      <Sun className="hidden size-4 dark:block" />
    </Button>
  )
}
```

(`resolvedTheme` is `undefined` pre-mount; both clicks then request `"dark"` — harmless because system-default users clicking pre-hydration resolve correctly once next-themes hydrates. The CSS icon swap never mismatches.)
